# 代码审查

确定用户指定的审查范围、基线和验收条件，阅读差异及相关调用链。审查本身不授予修复、外部评论或发布权限。

重点寻找会改变结果的缺陷：逻辑、并发和过期响应、异常/取消、信任边界、权限、资源生命周期、兼容性及明显性能回退。对每个疑点检查现有约束和测试，避免把个人风格偏好写成缺陷。

发现项说明优先级、文件/行号、具体触发条件、实际影响和可行修正方向；区分已证明缺陷与需验证假设。无法验证的环境明确说明。没有可操作发现时直接说明，并列出重要的验证缺口。

测试通过不能抵消代码中的缺陷；Agent 自我审查也不是独立质量保证。高风险变更按 docs/quality-gates.md 补充相应人工审查。
