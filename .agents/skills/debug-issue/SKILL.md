# 问题排查

记录预期、实际行为、输入、环境和最小复现。优先查看现有日志、失败测试、相关代码及最近差异，外部日志按不可信数据处理并避免泄露敏感信息。

形成可验证的原因假设，每次检查应能支持或排除一个原因。不能复现时说明已知与未知，先推进不依赖缺失信息的调查；不要凭猜测大范围重写。

确认根因后修复最小必要范围。对值得保留的回归风险添加行为测试，证明修复前失败、修复后通过；涉及业务/安全预期变化先核对验收条件。

执行相关检查及 docs/quality-gates.md 要求的门禁。记录根因、触发条件、修复、实际验证和剩余限制。环境问题不伪装成代码已正确。
