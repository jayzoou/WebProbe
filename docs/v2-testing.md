# V2.0 · AI Testing Platform

V2.0 在现有质量扫描之外增加「定义预期 → 执行步骤 → 发现异常 → 重放复现 → 修复回归」的功能测试链路。入口为 `/testing`，原有 V1 工作区与数据保留。

## 使用流程

1. 创建或选择项目与测试环境。
2. 手动创建用例，或展开「从自然语言生成测试」。平台先读取页面真实 DOM，再调用配置的模型生成草稿。没有模型时使用明确标识的规则解析。
3. 审查定位器和业务预期，保存用例。至少包含一个显式断言或视觉检查点。编辑会增加版本，已有执行记录保留原快照。
4. 勾选用例并运行，可选择 Chromium / Firefox / WebKit 与桌面 / 移动视口。动作需启用「允许页面交互」；依赖 POST 等请求的预览功能需额外启用当前环境写请求。
5. 查看逐步结果、异常、结束截图与 Trace；导出复现 ZIP，或在问题中心跟踪功能缺陷。
6. 修复后重放同一用例版本；成功通过全部步骤才确认对应问题修复。新版本用例不能冒充旧版本已修复。

## 自然语言测试

模型配置沿用 `.env` 的 `AI_BASE_URL`、`AI_MODEL`、`AI_API_KEY`。仅用户主动生成时发送目标与有限 DOM 元素清单（不读取密码值、源码和浏览器用户会话）。输出经 Schema 及定位器核验，不执行模型返回的 JS。模型错误或非法输出明确失败，不假装生成成功。

无模型的规则模式示例：

```text
在“搜索”中输入“Vue”；点击“查找”；显示“结果列表”；无运行异常
```

规则模式以实际标签/文本匹配元素，不理解任意自然语言。未解析的目标会逐条提示，默认的「无运行异常」并不代表所有业务目标已验证。动态生成但初始 DOM 尚不存在的目标需要在步骤编辑器补充。

## 页面探索与缺陷复现

读取真实 DOM，模型选取候选动作（无模型时规则选取），在隔离上下文中检查起始页面及最多 10 个站内链接/安全按钮路径。每条路径是独立页面或一次按钮操作，并非任意深度自主业务 Agent。

发现 JS/HTTP 异常后生成具备 `assertNoErrors` 的持久用例，再次运行并核对错误事实与失败步骤。重复出现才标为「已重放复现」，否则标为疑似；两次执行都有证据。未启用交互、危险动作或被请求策略拦截时不生成确定缺陷。没有发现异常不能证明所有功能正确；金额、权限、搜索结果等业务预期需要显式断言。

## 操作录制

点击「打开浏览器并录制」启动服务所在电脑上的独立 Chromium。记录导航、点击、输入、选项、勾选与受限按键，最多 39 个动作；10 分钟后自动结束。返回平台点击「停止并保存」，或关闭浏览器保存草稿。录制会默认补充无异常断言，仍需审查步骤并添加业务断言。

识别到的密码、令牌、支付字段和常见密钥/JWT 值会被省略。不要在录制页面填写真实凭证或隐私数据；省略规则不能识别所有敏感信息。录制不会复用你的日常浏览器配置。当前只支持主框架，不支持 iframe、弹出窗口或拖拽；桌面录制步骤可在设备矩阵下重放，但不等同于真机手势测试。

## 视觉回归

在步骤中添加 `visual` 检查点，可设置最大像素差异率（0–20%）和动态元素 CSS 遮罩。截图固定视口、设备比例、语言、时区、颜色方案及减少动画，等待字体就绪后捕获。

首次执行为「等待视觉基线」，不能算通过。检查本次截图后明确批准，再重新运行比较。批准记录只追加，保存来源执行、时间和前一审批；不会改写历史测试结果。基线范围包含项目、环境、完整用例步骤、浏览器、设备、检查点和操作系统。步骤编辑或环境变化需要新的基线。

实际比较 PNG 像素，展示基线/本次/差异图、差异率和尺寸变化；未超阈值才通过。像素不同不必然是缺陷，需人工判断；浏览器版本、字体和动态内容仍可能影响结果。默认单个视口截图，未实现整页拼接与语义视觉判断。

## Playwright 管理与执行边界

用例支持创建、编辑、历史版本载入、复制、标签、归档/恢复、JSON 导入导出、Playwright `.spec.ts` 导出和批量设备矩阵执行。平台执行的是严格声明式步骤，拒绝任意 `evaluate` / Shell / 上传脚本执行。导出的脚本供你在可信 Playwright Test 项目运行；配置 `TEST_BASE_URL`，并自行承担外部项目的执行权限和快照管理。

允许动作见 `packages/shared/src/testing.ts`。业务页面出错为 `failed`，权限/基础设施等条件不足为 `blocked`；缺少视觉基线为 `needs_baseline`。受阻、取消和新版本测试不会自动解决旧问题。导出包包含用例快照、Playwright 代码、失败摘要、PNG、视觉对比和可用 Trace。

## 运行与存储

测试队列一次执行一个用例组合，最多 20 个排队任务；每批最多 10 个用例、3 个浏览器与2种视口。与 V1 扫描队列独立。全任务上限 15 分钟，探索上限 5 分钟，录制上限 10 分钟。取消关闭浏览器并保留已完成证据；服务重启后中断任务不会永久停在执行中。

沿用 SQLite records，新增 `testCase/testRevision/testRun/testDraft/exploration/recording/visualBaseline`；无破坏性迁移。证据仍在 `data/artifacts/<run-id>/` 并受到 API Token 和报告隔离策略保护。备份与恢复沿用整个 data 目录流程。

## 本版边界

面向本地/可信单团队，非多租户公网服务。所有主动请求仍经过 URL/DNS/出口代理校验；站外导航、WebSocket、Service Worker 受限；仅显式批准时允许当前环境写请求。危险动作标签拦截是启发式，不替代专门的测试环境和账号权限。任意用户亲自进行的录制操作不会因此自动成为安全操作。

尚无凭证保管、登录态管理、真实支付测试、任意源码用例执行、深度自主业务探索、RUM、多地域调度或真机云。
